## Class A mechanism: client boundary guard

The client workspace boundary was an invariant enforced only by prose, while
`settings.json` allowed `Write(clients/**)` wholesale — any session could write
into any client's workspace.

`.claude/hooks/client-boundary-guard.sh` is a `PreToolUse` hook on
`Write|Edit|NotebookEdit`. It resolves the session lock at
`.claude/sessions/<session_id>.client`, normalizes the target path (textually,
since the file may not exist yet), and exits **2** — the only code that blocks —
when the write targets a different client's directory.

**Fails open by design when no lock is set.** A session that has not run
`/use-client` has no declared client, so there is no boundary to cross; failing
closed there would make the harness unusable before `/use-client` runs. This is
documented in CLAUDE.md § Traps.

Written for bash 3.2 (the macOS default) with no `set -u` and no `set -e`: an
aborted `PreToolUse` hook is read as *allow*, so the script must never abort
early. No `${#arr[@]}`, no associative arrays.

**Tested both directions, 23 cases total, all passing.** Allow path: same-client
relative and absolute, paths outside `clients/`, `clients/` root files, no lock
file, no lock for this session, empty `session_id`, non-path tools, sibling
source repos, malformed JSON, empty stdin, null `tool_input`. Block path
(exit 2): other client relative and absolute, deep project paths,
`notebook_path`, and two path-traversal escapes
(`clients/example-client/../_template/...` and `patterns/../clients/_template/...`).

## What I did not do

- **Nothing outside this repo.** ~37.1k of the 42.7k baseline — 87% — lives in
  Claude Code's system prompt, global agents, three globally-enabled plugins, and
  the claude.ai connectors. That is a larger lever than everything here combined,
  and it is global config affecting every project on this machine. Left as the
  user's call.
- **Did not touch the `NEVER`-style domain negatives** in the apple, blockchain,
  llm, backend, and frontend agents (28 imperative hits). `NEVER use tx.origin
  for auth`, `NEVER skip entitlement review` and similar are hard-won domain
  knowledge, not backseat driving. Only the PR-ownership lines were removed.
- **Did not compress agent or command descriptions.** They are the routing
  contract and were already discriminative; trimming them risks worse routing for
  ~11 KB of savings that mostly buys keyword coverage.
- **Did not add a commit-to-main guard.** README requires it and nothing enforces
  it, but the user declined it this round.
- **Did not resolve the Gemini leftovers in config.** `.env.template:52` still
  sets `DEFAULT_MODEL=gemini-2.0-flash` and `scripts/setup.sh:97` still prompts
  for a "Google API key (for Gemini)". With `.gemini/` gone these may be dead,
  but `GOOGLE_API_KEY` could serve non-Gemini client work, and changing a default
  model is behavior-changing. Flagged, not changed.

## Capability claims I could not verify

No `claude-api` skill reference on model-generation capability was consulted for
this refit — the available skill documents API surface (model IDs, pricing,
params), not what scaffolding a current-generation model still needs. Every cut
above is justified by evidence internal to this harness — measured duplication,
measured contradiction, dead code paths — and **not** by any claim about what
this model generation can now infer on its own. Those claims remain unverified.

## Sample size caveat

`n=1`. Only one transcript exists for this project directory, and it is the
session that ran this refit. There is **no usage history**: zero subagent spawns,
zero slash-command invocations other than `/refit`, and no data on context growth
past turn 9. Dormant-capability analysis was therefore impossible — no role or
command could be shown to be unused, so none were moved out of the always-loaded
path on usage grounds. Re-run the measurement after real work accumulates.
